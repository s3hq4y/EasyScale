# EasyScale 可行性评估报告

> 目标：做一个能方便修改 Windows「系统 → 屏幕 → 缩放」的工具，带托盘图标，
> 点击弹出主窗口，UI 为 Fluent UI 风格，并支持预设缩放大小。

评估环境：Windows NT 10.0.28000.0（26H1），x64，普通用户权限（未提权）。
所有结论均基于本机实测，非经验推断。

---

## 一、结论

**可行。** 核心的「改缩放并立即生效」已通过实测验证，无需管理员、无需注销。
托盘 + Fluent UI 为成熟方案，无技术风险。

.NET 8 SDK 已就位，解决方案已搭建，Core 层已完成并通过实测：

- `SetScale` 写路径可用：档位 rel 0→5→0 往返读回一致。
- 档位 ↔ 百分比映射已锁定：rel=0..5 精确对应 100/125/150/175/200/225%。

**结论：Core 层完成，可行性评估阶段结束，进入 App 层实现。**

## 二、关键实测证据

### 2.1 未公开 API 可用（决定成败的一点）

```
GET_DPI_SCALE (type=-3), id=sourceId=0, size=32
  rc=0    minScaleRel=0   curScaleRel=0   maxScaleRel=5
  注册表对照：SKG2703 的 DpiValue=0     ← 完全吻合

SET_DPI_SCALE (type=-4), size=24, 原值写回
  rc=0                                  ← 写接口可用
```

- 调用入口：`user32.dll!DisplayConfigGetDeviceInfo` / `DisplayConfigSetDeviceInfo`
- 关键：DPI 缩放是 **source（源）** 的属性，不是 target 的属性。
  头部 `DISPLAYCONFIG_DEVICE_INFO_HEADER` 的 `id` 字段必须填 **sourceId**。
- 结构体尺寸：GET = 32 字节（header 20 + 3×int），SET = 24 字节（header 20 + 1×int）。
- header.size 必须精确等于结构体实际大小，否则返回 `ERROR_INVALID_PARAMETER (87)`。

### 2.2 枚举活动显示器

- `user32.dll!QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS=2, ...)` 返回活动路径。
- 本机实测：1 条活动路径，adapter LUID = (81771, 0)，sourceId = 0，targetId = 4352。
- `DisplayConfigGetDeviceInfo(type=2, GET_TARGET_NAME)` 取显示器名与设备路径：
  - friendly = `H27S12`
  - devicePath = `\\?\DISPLAY#SKG2703#5&1f93f373&0&UID4352#{e6f07b5f-...}`

### 2.3 注册表结构（后备方案 / 交叉验证用）

位置：`HKCU\Control Panel\Desktop\PerMonitorSettings\<monitorKey>\DpiValue (REG_DWORD)`

本机实测存在两个键：
| monitorKey | DpiValue | 说明 |
|---|---|---|
| `SKG27031_15_07E6_36^ED1C3755...` | 0 | 当前物理屏（SKG H27S12） |
| `DELD0E67JQXBY2_24_07E3_2C^C9526677...` | 3 | **已拔除的 Dell 屏残留** |

> 重要：不能直接遍历 `PerMonitorSettings` 枚举显示器，其中混有非活动设备。
> 必须以 `QueryDisplayConfig` 的活动路径为准。

## 三、语义模型（防漂移核心）

```
相对档位 rel ∈ [minScaleRel, maxScaleRel]        （本机 0..5）
DpiValue(注册表) == curScaleRel                   （二者等价）
实际百分比 = 推荐百分比 + rel × 25%               （步长 25%）
```

- 支持百分比档位（通用）：100, 125, 150, 175, 200, 225, 250, 300, 350, 400, 450, 500
- **档位不写死**：由该显示器的 [min, max] 动态推导出真实支持的列表，
  避免出现「设置了但系统不接受」的档位。

**档位 ↔ 百分比映射已实测锁定**（见第六节验证记录）：

```
rel:      0    1    2    3    4    5
实测:   100% 125% 150% 175% 200% 225%
```

即 `实际百分比 = 推荐百分比 + rel × 25%` 成立，推荐档（rel=0）= 100%。

> 关键坑：交叉验证时，**调用方进程必须 DPI 感知**。
> 控制台进程默认不感知，`GetDpiForMonitor` 恒返回 96 DPI（100%），
> 会误判为「改档无效」。声明 PerMonitorV2 后才读到真实值。
> App 层已带 PerMonitorV2 manifest，不受此坑影响；
> 但任何测试/脚本若用 `GetDpiForMonitor` 交叉验证，必须先声明感知级别。

## 五、技术栈与架构

**技术栈**：.NET 8 + WPF + WPF-UI (Fluent 2) + H.NotifyIcon.Wpf

对比 WinUI 3：Fluent 更「正宗」，但托盘与非打包部署摩擦大，对本工具收益不值。

```
EasyScale/
  App.xaml(.cs)                     单实例(Mutex) + 托盘生命周期
  Tray/TrayIconHost.cs              H.NotifyIcon 封装
  Core/DisplayConfigService.cs      枚举活动显示器 / targetDevicePath
  Core/IDpiScaleApplier.cs          { Get, Set } 抽象
  Core/DisplayConfigDpiScaleApplier.cs   默认实现（走 -3/-4）
  Core/RegistryDpiScaleApplier.cs        后备实现（写 DpiValue）
  Models/MonitorScaleInfo.cs        Min/Cur/Max + 推导出的百分比档位
  Views/MainWindow.xaml             显示器列表 + 档位选择
  Views/SettingsWindow.xaml         预设管理
  Core/PresetStore.cs               预设持久化 (JSON)
```

**设计原则**（对应「减少硬编码 / 杜绝语义漂移 / 可持续开发」）：
1. `IDpiScaleApplier` 抽象 + 两种实现，策略可切换 —— 未公开 API 万一失效，
   上层无需改动即可回退到注册表方案。
2. 缩放档位由 [min, max] 动态生成，不硬编码百分比数组。
3. `DpiValue == curScaleRel` 的等价关系集中注释，禁止两处各写一套。
4. 未公开类型号（-3/-4）集中定义为具名常量并标注「未公开」。
